> 用户提出的 5 点：① 教案大纲 ② 每个课的教案 ③ 教案像 git 那样的改进经验 ④ AI 辅助 ⑤ 所有课程都能分出一份大纲

## 一、现状与问题

现有 `lesson.html` 是**演示壳**：

- 3 份教案写死在 `LESSONS` 数组里（第 6/7/8 章），**与 `COURSES` 完全无关** ——
  切到「操作系统」还是显示数据结构的三章，属于**编造**。
- 粒度混着：`meta` 写「数据结构与算法 · 4 课时」，既是章级又暗示课时。
- 没有任何版本概念：改了就覆盖，改坏回不去。
- 「新建」「编辑」两个按钮只 `alert("待接入")`。
- 唯一的 AI 关联是一段静态说明文字（`.ai-box`）。

**重构目标**：从「一份静态列表」变成「按课程组织的、可持续演进的教案资产库」。

## 二、信息架构（四层）

```
课程 COURSE（每门课一份大纲）
  └─ 教案大纲 Syllabus        课程级框架：章 / 课时数 / 核心知识点 / 整门课目标
       └─ 课时教案 Lesson     每次课一份：目标 · 重难点 · 流程 · 作业 · 学情提示
            └─ 版本 Version   git 式演进链：初稿 → 编辑 → 课后改进 → 采纳 AI 建议
```

**粒度约定**：**大纲切到「章」，教案切到「课时」**。
一门课 = 1 份大纲 + N 份课时教案。大纲是「这一学期教什么、什么顺序、几课时」，
课时教案是「这一次 45 分钟怎么上」。

## 三、五个功能点的设计

### ① 教案大纲（课程级）

- 每门课一份，结构：整门课目标 → 章列表（章名 / 课时数 / 核心知识点 / 本章课时教案数量）
- 大纲本身**也可编辑**（增删章、改课时数、调整顺序）
- 大纲是**导航**：左栏树「章 → 课时」两层，点课时进教案
- 大纲是**AI 的输入**：AI 生成课时教案时，从大纲取「本章核心知识点」作为约束

### ② 每个课的教案（课时级）

沿用现有结构化字段（这是好东西，保留），补两项：

| 字段 | 说明 |
|---|---|
| 教学目标 `goals` | 保留 |
| 教学重点 `keyPoints[]` | 保留，数组（便于 diff 与 AI 引用） |
| 教学难点 `hardPoints` | 保留 |
| 课堂流程 `steps[]` | 保留，**新增每步时长**（用于页头显示「导入 8′ · 探究 22′ …」） |
| 作业布置 `homework` | 保留 |
| 学情提示 `note` | 保留 |
| **课时状态** `status` | 新增：草稿 / 待上 / 已上 —— 左栏树上的状态点用它 |
| **上次上课日期** `taughtAt` | 新增，与「课后反思」配套 |

课时状态只做三个，够用且不啰嗦：

```
草稿 draft   —— 还没写完，灰
待上 ready   —— 定稿了，等上课，蓝
已上 taught  —— 上完了，绿
```

### ③ 教案像 git 那样改进（本方案的核心）

把每次保存变成**一次提交（commit）**，而不是覆盖。

**commit 结构**

```js
{
  id: "v3",
  at: 1759270000000,
  by: "李老师",
  kind: "init" | "edit" | "reflect" | "ai" | "revert",
  msg: "课后改进：先让学生手推分区过程，再讲代码",
  snap: { goals, keyPoints, hardPoints, steps, homework, note },   // 该版全文快照
  reflect: { date: "2026-09-28", saw: "学生对分区指针移动卡住", todo: "下次先发卡片手工模拟" }
}
```

三种能力：

1. **版本历史**（时间线，倒序）
   每条显示：版本号 · 提交说明 · 作者 · 时间 · 类型徽标（初稿/编辑/课后改进/AI 建议）。
   点任一条可「查看这一版」。

2. **对比（diff）**
   选两版 → 结构化逐字段对比，用 `+` 绿 / `−` 红（配符号，不只靠颜色）：

   | 字段类型 | 对齐方式 |
   |---|---|
   | 标量（目标 / 难点 / 作业 / 学情） | 按句切分做最长公共子序列，行级增删 |
   | 数组（重点 / 流程） | **按内容**做最长公共子序列；相邻的「删 + 增」配对成「同位置改动」 |

   不做真文本 diff 库（零依赖），字段级 + 行级已经够表达「这一版改了什么」。

3. **回退**
   🔴 **语义必须是「把旧版内容作为一次新提交」，不是删历史。**
   和 `git revert` 一致：历史只增不减，回退也是一条 commit（`kind: "revert"`，
   说明里写「回到 v2 的内容」）。这样用户永远不会因为点错而丢东西。

**关于「分支」**：教学场景确实有「同一知识点两种教法并行试」的需求，
但真分支（merge / 冲突解决）对纯静态站太重、对教师也太抽象。
**建议先不做**。替代做法：从某个旧版本「另存为新课时教案」，当成对照试验。
若将来要做，落地形态是「一课时多份方案 + 标记主用方案」，而不是真分支。

**「改进经验」的两层含义**（用户原话「改进经验」）：

- **每次提交的说明**（`msg`）—— 我这一版改了什么、为什么
- **课后反思**（`reflect`）—— 上完这节课的观察，是产生下一版改进的输入

这条链路是「教案越用越好」的引擎：

```
上课 → 记课后反思 → AI 读「反思 + 班级学情 + 现有教案」提改进建议
     → 教师采纳 → 作为新 commit 提交 → 下次上课用新版
```

### ④ AI 辅助（四个落点）

| 场景 | 输入 | 输出 |
|---|---|---|
| ① 生成课时教案初稿 | 大纲的章 + 课时名 + 核心知识点 | 一份可编辑的结构化教案（作为 v1 提交） |
| ② 课后改进建议 | 现有教案 + 最近一次课后反思 + 该班学情 | 2–3 条具体修改建议 → 采纳即新版本 |
| ③ 版本对比解读 | 两版 diff | 「这一版主要改了什么、可能的教学意图」 |
| ④ 教案转出题 / 讲评 | 教案重难点 | 出题（联动 `exam.html`）/ 课堂讲评提纲 |

**形态建议**：和「课表导入 · 方式三」保持完全一致 ——
把 `prompt` + 上下文写进 `st_agent_task`，跳到 `agent.html` **去处理**。
理由：零依赖、不碰 API Key 逻辑、交互语言一致（用户已经见过一次）。
`agent.html` 的 AI 解析功能做完后，同一套「读任务 → 干活 → 回填」的管线可复用。

页内**不**内嵌聊天框 —— 那是 `agent.html` 的职责，两个入口会打架。

### ⑤ 所有课程都能分出一份大纲

- 大纲按 `courseId` 存，`lesson.html?course=ds` 与侧栏「我的课程」联动
- 页面顶部一个课程切换器（下拉），显眼地表明「这是哪门课的大纲」
- 🔴 **新建的课程没有大纲 → 明说，不编造。**
  显示空状态：「这门课还没有教案大纲」+ 一个「按课程信息新建大纲」按钮
  （生成空骨架：一章 / 若干空课时，由教师自己填）。
  **绝不把数据结构的教案显示给「编译原理」** —— 与第 19 轮
  `class.html` 处理「未绑定班级」的口径一致：**宁可空，不许假**。

## 五、数据模型与存储

```js
// 大纲：一门课一份
st_syllabus = {
  "ds": {
    courseId: "ds",
    goal: "整门课目标…",
    updated: 1759270000000,
    chapters: [
      { id: "c7", title: "第 7 章 · 排序", hours: 4,
        points: "五类排序的复杂度与稳定性",
        lessonIds: ["ds-c7-1", "ds-c7-2", "ds-c7-3"] }
    ]
  }
}

// 课时教案：一份教案一条，内含版本链
st_lessons = {
  "ds-c7-2": {
    id: "ds-c7-2", courseId: "ds", chapterId: "c7",
    title: "第 7 章 · 第 2 课时 快速排序",
    minutes: 45, status: "ready", taughtAt: "",
    head: 2,                    // 当前采用的版本下标
    commits: [ … ]              // 只增不减；当前内容 = commits[head].snap
  }
}
```

**不冗余存 `fields`**：当前内容一律从 `commits[head].snap` 取 ——
曾经想过「冗余一份省得回溯」，但那会让同一份内容有两个真相，迟早不同步。

**容量**：一份快照约 1–2 KB。一门课 20 课时 × 10 版 ≈ 300–400 KB，localStorage（5 MB）够用。
保底策略：单份教案超过 30 版时，把最旧的非 `reflect` 版本折叠（历史里保留一行「更早的 N 个版本已折叠」）。

**读写**：沿用 `nav.js` 里的 try/catch 套路 —— `file://` 下 localStorage 会抛错，退化为内存态，不炸页面。

## 六、与既有约定的衔接（改动前必看）

| 事项 | 做法 |
|---|---|
| 深链 | `lesson.html?course=ds&lesson=ds-c7-2`。**侧栏高亮复用 `nav.js` 的 `currentIndex()`**：精确比对失败 → 退回裸页名 → 「教案」项亮。第 15 轮加的两步走刚好覆盖这种深链 |
| 弹窗 | 一切都走 `core.js` 的 **`pageModalHost()` / `closePageModal()` / `pageModalEsc()`**，不要用壳的 `#modalHost`（iframe 里取不到） |
| 课程切换 | 数据来自 `nav.js` 的 `COURSES`；页面顶部切换器**不改侧栏**，只改自己的 URL 与内容 |
| 大纲/教案的增删 | 校验与写库放在 `nav.js`（像 `createCourse()` 那样**只写一份**），页面只负责收表单与重渲染 |
| 状态可观测性 | 像 `#weekBody.dataset.source` 那样，关键状态挂 `data-*`，**界面可以不显示，但验证器要读得到** |
| 验证器 | 新增断言同时进 `verify-site.cjs`（结构/纯函数/静态 id 引用）与 `dom-smoke.cjs`（真实交互） |
| 时间相关 | 「上次修改 2 天前」「是否已过期」这类文案一律走**纯函数 + 可注入的 now**（`computeFocus` 的先例），断言不许依赖运行时刻的真实时间 |

## 七、纯静态约束下的诚实口径（答辩要讲）

- **没有服务端 → 版本历史只存在本机浏览器**。换设备看不到，清缓存会丢。
  正式版本应由后端存教案与版本链，前端只是视图。
- **没有真并发 → 不存在「多人协作冲突」**。所以不做 merge，也不假装有。
  「教研组共享教案」在纯静态下只能是单浏览器内的模拟。
- **AI 全部走用户自己的 API Key**，且经 `agent.html` 统一处理；没配 Key 时要有可读提示。
- **教案 → 出题 / 讲评是「引用」，不是自动执行**：AI 读教案生成建议，教师确认后才生效。

### 这一轮踩的坑

**① 🔴 `renderLessonPanel()` 忘了紧跟 `renderTabBody()` → 标签区永远空白。**
详情面板先渲染「标题 + 标签栏 + `<div id="tabBody">`」，内容由 `renderTabBody()` 填。
漏掉这一步，页面看起来正常（标题、标签都在），点进去却什么都没有。
→ jsdom 加了「六个分节齐全 / 版本 4 条 / 对比有 + 行」等交互断言；
→ 桩侧再加一道**静态**断言：`<div id="tabBody"></div>`; 之后必须紧跟 `renderTabBody();`。

**② 静态 id 引用检查有两份实现，只改到一份。**
`verifyContentPage()` 里一份、`verifyGlobal()` 里一份，几乎逐字相同。
加了「`el.id = "xxx"` 也算已声明」之后，`lesson.html` 仍报 `#flash` 缺失 ——
因为报错的是另一份。→ 抽成唯一的 `danglingIds()`，两处共用。
（与「侧栏两份渲染」「弹窗两份」是同源的老毛病：**同一件事只能有一处实现**。）

**③ 按「下标」对齐的数组 diff 噪声太大（实测才发现）。**
设计稿原本写「数组按索引对齐」。实际用起来：在「教学重点」中间插一条，
它后面每一条都被标成「改动」，渲染出 2 行删除 + 3 行新增，真正的改动被淹没。
→ 改成**按内容**做 LCS，再把相邻的「删 + 增」配对成「同位置改动」：
插入只占一行，位置上的修改才显示 −/+ 两行。断言覆盖「中间插一条只标一行」。

**④ 测试自己写错两次（都是把状态想当然）。**
- 「删到只剩一行」：我在删之前先点了一次「添加一步」，总数是 `rows0 + 1`，
  却按 `rows0 - 1` 算 → 剩 2 行。改成「一直删到只剩 1 行」的循环，不依赖初始行数。
- 「无效回退」：前面刚回退过一次，`index 0` 已经不再是当前版本了，
  于是第二次调用照样成功。改成拿 `LESSONS[...].head` 去试。
