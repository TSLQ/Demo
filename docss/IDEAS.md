## 灵感 01 · 一站式工作台（三层架构）

**提出时间**：2026-09-29
**状态**：层 2「实训活动」已实施教师侧（2026-10-02）；**层 3 已实施**（2026-10-05 第 37 轮工作台 +
**第 38 轮教学模拟器**，**第 39 轮改成 WorkBuddy 三栏任务台形态**，见下方「实施记录」）

### 用户原话

> 我觉得可以做成一站式工作台，学生和老师都是一站式工作台，老师可以在里面发布实训活动，
> 学生可以参与，然后也可以像 workbuddy 一样做临时工作台，然后老师可以像 workbuddy 一样
> 有临时工作台，也可以做个临时工作台给学生用，这样保障了很多功能缺失的问题，
> 各个领域都有自己的东西，我们永远做不完，但是这样就可以了。

### 核心洞察

**功能是发散的（永远做不完），但容器是收敛的。** 与其穷举领域功能，不如提供"工作台"这个容器，
让使用者按需生成 / 配置内容。这与 WorkBuddy 自身形态一致。

### 三层结构

| 层 | 名称 | 谁定义内容 | 存储 | 性质 |
|---|---|---|---|---|
| 3 | 临时工作台 | 使用者按需生成 | `st_workbench_*` | 开放，用完即弃，可固化 |
| 2 | 实训活动 | 教师发布，学生参与 | `st_activities` | 半开放，项目制 |
| 1 | 课程与教学骨架 | 我们预置 | 静态页面 + 本地数据 | 确定，长期 |

**三层代表三种"确定性程度"** —— 越往上越开放，所以产品天然可扩展，不必穷举领域。

### 已确认的决策（2026-09-29 用户回答）

1. 临时工作台形态 = **卡片容器（确定性） + 一句话新建（生成性）** 的混合
2. 实训活动 = **先只做「发布」与「参与」两屏**，批阅/统计留后
3. 本轮只出方案，不写代码

### 关键技术判断

- **`agent.html` / `agent-student.html` 已具备 80% 地基**：对话输入、气泡、
  `toolChainEl` 工具链动效、`mdToHtml` Markdown 渲染、关键词意图匹配、LLM 兜底。
- 改造点：把 **Markdown 回复升级为「结构化结果卡片」渲染** —— 管线不用重写。
- **对 LLM 的诚实口径**（答辩要讲）：**分两种形态，别混着说** ——
  · **卡片（第 37 轮）**：不生成可执行程序，而是**用模型把自然语言意图转成结构化结果数据**，前端渲染成界面。
    这在纯静态站能力边界内，演示效果真实。
  · **模拟器（第 38 轮）**：**真的生成可执行的单文件 HTML**，在 `sandbox="allow-scripts"`（不给同源）
    的 iframe 里跑。所以它能"动手玩"，不是只看。**触发条件是有 Key** —— 没有 Key 就如实说，
    绝不假装生成了。这两条答辩时都要讲清楚，否则会被问"到底生没生成"。

### 待拍板的决策点（尚未回答）

1. ~~临时工作台入口位置~~ → **已定：独立新页 `workbench.html`**（第 37 轮实施），
   侧栏「智能体」组里排在「AI 助手」前面（它是容器，助手是对话）
2. ~~卡片存储粒度~~ → **已定：存结果快照**（第 37 轮实施，理由见「实施记录」）
3. ~~实训活动 vs 学生「我的作业」：合并还是分开~~ → **已定：分开**（2026-10-02 实施时按建议分开）
4. **模拟器要不要让学生也能"自己发起一个模拟"** —— 当前只有教师生成、教师下发（第 38 轮的决策是
   "工作台独立下发"）。若放开学生侧，要先想清楚：学生生成的代码发给谁、谁审。
5. **模拟器的"老师看过"要不要留痕** —— 现在只是生成后自动开预览（软约束）。
   若要做硬约束（未预览过不许下发），需要在 `SIMS` 上加 `previewedAt` 字段。

## 实施记录 · 层 3 工作台（2026-10-05 第 37 轮）

**用户诉求原话**：用户说「智能体这一栏，学生和老师都要加一个：**工作台**，就像 workbuddy 这样的东西」。

**入口**：`workbench.html`（`data-role="both"`），侧栏「智能体」组里排在「AI 助手」**前面** ——
它是**容器**，AI 助手是**对话**。

**核心判断：存快照，不存配方。** 卡片里是**当时跑出来的那批行**（`secs[].lines`），不是
"那句话 + 技能 id"。存配方的话，用户改了技能开关或输入后，历史卡片内容会**自己变** → 历史不可信。

**与 agent 页的关系**：`routeSkills` → `runSkillChain` 是**同一条管线**，
所以用户在左栏关掉的技能，工作台里也生成不出来 —— **技能库是整个应用的「能力总开关」**。
agent 页的结果卡上加了「收进工作台」，把对话产物沉淀成可再用的卡片。

**两个共享件在这一轮上收**（原来 agent 两页各一份，工作台一来就要变三份）：
- `runnableIds()` / `runSkillChain()` → `nav.js`
- `renderLines()` → `core.js`，**代码块 + Markdown 表格合并处理**（分开处理时块里的 `|` 会被表格规则拆烂）

## 实施记录 · 层 3 教学模拟器（2026-10-05 第 38 轮）

**用户诉求原话**：

> 这个工作台，我想的是像 workbuddy 做工作台一样，比如化学老师需要一个简单的化学模拟，
> 让学生在电脑上模拟，就可以让 ai 生成一个模拟的工作台，然后下发给学生进行尝试这些

**这一句把层 3 的形态说透了**：不是"收纳 AI 的答复"（那只是卡片），而是
**让 AI 现做一个能动手玩的小工具**，老师看好之后下发给学生 —— 从"读的东西"变成"要跑的东西"。

**已实现**

| 能力 | 落点 |
|---|---|
| 一句话 → LLM 现场写单文件 HTML | `nav.js` 的 `generateSimHtml()` + `simSystemPrompt()` / `simUserPrompt()` |
| 模型不听话时抠出 HTML | `extractHtml()`（去围栏 → 起截 DOCTYPE → 止于 `</html>`） |
| 不合格的生成结果宁可拒绝 | `validateSimHtml()`（完整性 / 长度 / **禁外部请求**） |
| 沙箱试玩（不给同源） | `workbench.html` 的 `iframe sandbox="allow-scripts" srcdoc=…` |
| 下发给在课学生 | `sendSimTo()` + 名单来自 `enrolledStudentsOf(课).key` |
| 学生试玩并写「我观察到」 | `openSimStudent()` + `addSimFeedback()` |
| 老师看学生反馈 | `openSim()` 里的「学生反馈」一节 |
| 设置页真测连接 | `settings.html` 的 `testConnection()`（以前是假 alert） |

**五条设计判断**（答辩可讲）

1. **沙箱不给同源** —— `allow-scripts` 但不给 `allow-same-origin`：生成的代码拿不到
   应用的 localStorage / Cookie / DOM。这是"敢让模型写代码并跑起来"的前提。
2. **不许假装生成了** —— 演示模式 / 没 Key / 请求失败 / 返回的不是 HTML，一律如实说 + 指路
   「设置 → 模型接入」。**这是本作品对 LLM 的诚实口径在 UI 上的体现**。
3. **先预览、后下发** —— 生成后自动进预览，老师得真的点过；不给"一键直发"。
   生成的代码没人看过就流到学生手里，是这个功能最危险的失败方式。
4. **系统提示词硬约束"不给结论"** —— 直接写进 `simSystemPrompt()`：
   "不要写「所以答案是…」。要让学生通过操作自己看出来"，并要求页面上放一个「我观察到」输入框。
   **教学法不是靠老师自觉，是写进约束里的。**
5. **禁外部请求是硬校验，不只是提示词** —— 沙箱里本来也加载不出来，
   留着只会让模拟"看起来坏了"。所以校验层直接拒收带 CDN 的 HTML。

## 实施记录 · 层 3 三栏任务台（2026-10-06 第 39 轮，照抄 WorkBuddy 工作台形态）

**用户诉求原话**：

> 不是，你知道 workbuddy 吗，你搜一下他的资料库里面的工作台，直接抄，缝合进来就行了

**这一句是形态纠偏**：第 37/38 轮把工作台做成了「上边一长条卡片墙 + 生成区」，
不像 WorkBuddy 那种**任务型工作台**。第 39 轮推倒重做，照抄 WorkBuddy 的**左中右三栏**形态。

**抄到的形态（用户拍板"中对话，右结果区"）**

```
左：任务列表（按空间分组 · 状态标记三种 · 悬停「⋯」置顶/重命名/改空间/归档/删除）
中：对话（当前任务的完整对话历史 + 工作模式三选一 + 输入）
右：结果区（概览 / 产物 / 全部文件 / 变更 —— 四个视图，四个都做真实内容）
```

**已实现**

| 能力 | 落点 |
|---|---|
| 任务列表按空间分组，状态优先级聚合 | `nav.js` 的 `taskSpaces()` / `groupMark()` / `taskMark()` |
| 任务 = 一段对话 + 它摘出来的产物 | `TASKS` 里的 `messages[]` 是主，`artifacts/files/changes[]` 是派生记录 |
| 工作模式 Craft/Plan/Ask **真起作用** | `canProduce()` / `modeStep()` / `modePlan()` + `handle()` 三条真分支 |
| 结果区四视图接真实数据 | `renderOverview/Artifacts/Files/Changes`（模拟器宿主搬进「产物」视图） |
| 重命名 / 改空间就地编辑（不用 prompt） | `openFieldEditor()`（挂在 `pageModalHost()` 上） |

**四条设计判断（答辩可讲）**

1. **对话是主，产物是摘出来的** —— 一个"任务"承载完整对话上下文，产物（卡片/文件/变更）
   是从对话里的动作**派生记下来的**。删任务不删产物（如实说明），因为产物是工作台级的、可复用。
2. **工作模式不是装饰** —— 三种模式走**三条真代码路径**：`执行`规划完直接做（改动前仍问一次）；
   `规划`只摊开步骤、**点「开始执行」才动手**；`问答`只回答、**不写盘不留产物**。这是"工作模式"该有的语义。
3. **状态优先级：待确认 > 已完成未读 > 进行中** —— 左栏分组收起时聚合显示优先级最高的那一个，
   用户一眼看出"有几件事在等我"。
4. **不用 `window.prompt`** —— 沙箱 / 自动化里都没有，是死路；就地弹窗两种环境都稳。

## 实施记录 · 层 2 实训活动（2026-10-02）

**入口**：教师端侧栏「教学」组 → **实训管理**（`training.html`）；徽标 = 待教师确认的学生发起活动数。

**已实现**

| 能力 | 落点 |
|---|---|
| 一句话目标 → **引导骨架**生成 | `nav.js` 的 `draftSkeleton()`（预置路径库命中 → 通用骨架兜底） |
| 预置「创造史路径库」 | `PATH_LIB`：圆面积·割圆术 / 勾股定理·面积拼补 / 瞬时变化·极限，各 4 步 |
| 发布实训 + 骨架可编辑 | 弹窗里**实时预览**骨架；创建为草案 → 右栏逐步改措辞 → 发布 |
| 骨架步骤 增 / 删 / 上移下移 | 数据层 `addStage`/`removeStage`/`moveStage`/`moveStageBy`（"插到谁前面"，不用下标） |
| 开放性开关 | `openEnded` —— 允许学生偏离骨架（灵感 02 的核心） |
| 学生的新发现 + 推荐方向 | `findings` + `toggleFindingPin()`（参见灵感 02 的收口方式） |
| 学生发起型活动 | `origin: "student"` —— 已并入同一张表，**待教师确认后才发布** |

**落地的两条硬规矩（都有断言盯着）**

1. 🔴 **不给答案，给路径**：骨架的每一步只有「引导问题 / 线索 / 动手做」，
   终点结论写在 `PATH_LIB[].answerNote` 里**只给教师看**，`skeletonFromPath()` 明确不拷进骨架。
   断言：`draftSkeleton(...)` 里不出现 `answerNote`，也不出现 `πr²` / `a²+b²=c²` 这类终点结论。
2. **如实标注来源**：命中哪条路径 / 通用骨架，都写在界面上；不假装「AI 联网检索过了」。
   纯静态站不能真联网 → **这段管线固化成本地路径库**，答辩照这个口径讲。

**待做（学生侧）**：`training.html` 目前是教师管理端。学生「参与」屏还没做 ——
参与页要能：看骨架并逐步推进 / 记下自己的路线 / 标记「这是我的新发现」/ 拉同学和老师 / 学生自己发起实训。

## 灵感 02 · 学生发起的探究式实训（Search-then-Construct）

**提出时间**：2026-09-29
**状态**：**骨架侧已实施**（2026-10-02 随层 2 一起落地）；**学生端「参与 / 发起」屏待做**

### 用户原话

> 学生可以对某一个东西发起实训，可以拉同学或者寻求老师一起完成某一个实训，
> 比如课程只教学了圆的面积公式，但是这个面积公式是怎么创造出来的，学生可以发起实训，
> 然后 ai 会尝试搜索有没有现成的整套流程，在这个案例中就是 ai 会搜索这个公式是怎么创造出来的，
> 然后作为实训方向骨架，一步步引导学生创造出这个公式，
> 同时如果学生有新的发现，可以尝试让学生自己多试试新的方向，
> 万一学生能创造出属于自己的方案呢

### 我的理解 —— 三件事叠加

**① 学生可以主动发起**（不只是响应教师发布的活动）
—— 这是对灵感 01 的重要补充：实训活动的发起权不再只属于教师。

**② 协作对象可拉人**：拉同学、请老师 → 实训是**协作空间**，不是个人作业。

**③ AI 的介入方式：先检索「人类已有的创造路径」，再转化为引导骨架**

这是最漂亮的一点。AI 不是直接给答案，而是：
```
学生提问「圆面积公式怎么来的」
  → AI 检索：人类历史上这个公式是怎么被创造出来的（阿基米德/刘徽割圆术…）
  → 提炼成一条「探究路径骨架」（逐步逼近的引导步骤）
  → 一步步引导学生自己走完这条路径（而不是直接告诉结果）
```

**④ 开放性兜底：允许学生偏离骨架，尝试自己的方向**
> 「万一学生能创造出属于自己的方案呢」

这句话是整条灵感的价值顶点 —— 它把产品从"高效教学工具"提升到
**"保留创造可能性的学习环境"**。这与"标准答案导向"的常规教育产品形成鲜明差异。

### 为什么这条灵感特别有价值（对比赛的意义）

1. **它质疑了教育产品的一个隐含假设**：教学 = 把已知结论高效传递。
   而它主张：教学可以 = **让学生重走一遍人类的发现过程**，甚至走出新路。
2. **它天然需要 AI**（检索创造史 + 提炼骨架 + 动态引导），不是给常规功能套 AI 皮。
3. **它与「圆面积」这个例子咬合得极好**：割圆术是"把未知化归为已知"的典范，
   本身就是可被学生重新发现的路径 —— 例子选得精准。
4. **它把"实训"从技能训练提升为"探究"**：实训 = 项目式学习 + 科学发现的重演。

### 待确认 / 待设计的点（2026-10-02 更新）

- ~~**骨架的形态**~~ → **已定：一串带序号的步骤**，每步 = 标题 + 引导问题（往哪想）+ 线索（去哪儿找）+ 动手做（一件事）。
  不做有向步骤图 —— 骨架要的是「能带着走」，不是画得漂亮。
- ~~**"检索现成整套流程"在纯静态站如何落地**~~ → **已落地**：预置 `PATH_LIB`（割圆术 / 勾股定理 / 极限思想）
  + 关键词命中（按命中字符数打分，阈值 2，避免单字误命中）+ 通用骨架兜底，来源如实标注。
- **协作如何模拟**：单浏览器 localStorage 的既有约束下，多人协作只能演示性质（当前参与者/新发现是演示数据）。
- ~~**"学生走出新方向"如何被系统识别与记录**~~ → **已定**：不假装 AI 能判定创新性，
  退化为「**学生主动标记新发现 + 教师标为推荐方向**」（`findings` + `toggleFindingPin`）。
- **与灵感 01 的关系**：这是「实训活动」这一层的一个**新分支**（学生发起型），与教师发布型并列 ——
  已进同一张表（`origin: "student"`），学生发起的活动**待教师确认后**才发布。


### 与既有产品叙事的衔接

既有教育叙事是「教学闭环（答疑→批改→分析→回答疑）+ 无障碍（教育公平）」。
本灵感可扩展为**第三条叙事线**：

> **从"学会"到"重新发现"** —— 不止让学生掌握结论，还让他们有机会重走创造之路。

## 灵感 03 · （占位，待补充）
