# Agent 设计架构（现状版）

> 与代码同步：`docs/agent.html`、`docs/agent-student.html`、`docs/assets/nav.js`（第 62 轮后）。
> 本文只写**已经实现并能被验证**的东西，不写规划。

## 一句话定位

**确定性编排 + 模型只负责内容生成。** 不做 ReAct 自由循环，路由与步骤都不交给模型。

## 五层结构

| 层 | 落在哪 | 职责 | 边界（它不做什么） |
|---|---|---|---|
| 交互 | `agent.html` / `agent-student.html` | 收发消息、动作链、结果卡、图表渲染 | 不做路由判断，不拼提示词 |
| 编排 | `nav.js`：`routeSkills` → `runnableIds` → `planFromChain` → `runSkillChain` | 选技能、展开步骤、按序调度、回收结果 | 不生成内容 |
| 技能 | `nav.js`：`SYSTEM_SKILLS` / `GROUP_SCENES` / `ATOMIC_SKILLS`，共 27 条 | 定义「什么话该做什么事」，`steps` 只是数据 | 不自作主张决定跑不跑 |
| 模型 | `nav.js`：`llmChat` ← `fitContext` | 把材料写成文（教案、题面、解读、图表 option） | 不决定流程、不决定调几次 |
| 数据 | 浏览器存储，键 `基名:角色:账号` | 课程、教案、课件、试卷、行为、画像、对话记录 | 无后端，不跨设备 |

**横切（每层都要成立，不占层）**：账号分桶 · 上下文预算 · 中断信号 · 对话记录。

## 一次对话的控制流

1. `handle(text)` —— 置 busy、建中断信号、取最近 6 轮历史
2. `routeSkills()` —— **纯关键词打分**：系统层全挂；群组层取前 2（没命中就挂当前课程/班级）；原子层取前 3
3. `runnableIds()` + `planFromChain()` —— 过滤掉关掉的/无执行器的；把 `steps` 展开成动作链，**写步强制插 `wait`**
4. `runSkillChain()` —— 逐个执行，单个失败只记入 `failed`，不中断整条链；需要成文的技能才调 `llmChat`
5. `settle(runs)` —— ✓ 只认 `executed`，失败显示真实错因；随后 `pushAgentChat()` 落一条记录、`finishRun()` 复位

出口只有一个：成功、失败、被中断，都从第 5 步返回。

## 为什么这样切

**① 控制权归代码。** 路由是查表打分，步骤是技能里的静态数组。代价是「不会自己想办法」，收益是可重放、可单测、可限预算——每次对话跑哪几条、花几次调用，事先就能算出来。

**② 模型只出现一次。** 27 条技能里只有 4 条会调模型（起草教案、改进、差异解读、生成图表）。其余是本地计算，没 Key 也能跑。**没接模型时如实拒绝，不塞假内容。**

**③ 写操作必须停。** 教师端会改数据的技能标 `kind:"write"`，`planFromChain` 见到就插一道「等待确认」；确认后走 `runAgentStep` 真执行，缺对象时返回 `ok:false` 并说明原因——**不把失败画成 ✓**。学生端没有任何写技能。

**④ 上下文是装配出来的。** `fitContext` 按 3000/6000/4000/3000 字符四档分配，超限截断并在正文里留「省略 N 字」；历史先折叠成一行、再丢最老的，相邻同角色合并（否则部分服务商直接 400）。压缩情况写进对话记录。

**⑤ 画像从行为推，且真的进提示词。** `behaviorProfile` 统计行为，`fitPersona` 门槛 ≥3 次提问才判偏好；`sys-persona-sync` 勾选即 100% 触发（`alwaysRun`），有变化才写回，没变化就说「已是最新」。画像经 `personaPromptBlock()` 拼进 system。

## 已知边界（答辩会被问，先自己说）

- 协同是**单浏览器模拟**：两个身份靠同一份本地存储，不是真多用户
- 对话记录是**摘要级 trace**（问了什么、跑了哪些技能、成败、耗时），不是每次模型调用的完整 prompt 与入参出参
- 没有**评测集**：1700+ 条断言验的是契约与结构，不验「这份教案能不能上课」；质量层靠 AI 自评 + 人工抽检
- 技能路由是关键词，**同义改写的召回有限**；写成「帮我看看这课」这类泛问时靠群组层兜底

## 可抄进设计文档的一段（约 300 字）

> 系统采用五层结构：交互层只负责呈现，编排层持有全部控制权，技能层以数据形式描述能力，模型层只承担内容生成，数据层按账号分桶存储。一次对话经「路由 → 展开 → 执行 → 回收」四步完成，路由为确定性关键词打分，不调用模型；教师端的写操作在动作链中强制插入确认步，确认后真实执行，失败时返回具体原因而非假装成功。上下文按系统提示、任务材料、检索片段、历史对话四档预算装配，超限截断并记录。能力扩展只需新增一个技能对象，不改调度代码。系统在未接入模型时如实拒绝生成请求，不返回占位内容。
