## 3. 逐节参考

### §1 作品概述（~200 字）

- **该写什么**：一段话讲清「双端教学系统」+ 纯静态形态 + 服务对象。别铺垫背景。
- **可用事实**：18 个页面 · 教师端／学生端两套菜单 · 浏览器直接打开即用 · 无需安装部署。
- **示范开头**（可改）：
  > 智课助教 SmartTutor CS 是一套面向计算机专业的双端教学系统：教师端负责备课、出题、发布与学情跟踪，
  > 学生端负责阅读、答疑、作业与探究。整套系统是一个纯静态站点 —— 不依赖服务器与数据库，
  > 打开浏览器即可运行。

### §2 问题与场景（~400 字）

- **该写什么**：把痛点写**具体到动作**，不要写「教学效率低」这种空话。建议挑 2–3 条：
  - 备课成果散落各处：教案、课件、题目、作业各在不同工具里，**来回搬运**；
  - 学生的「不懂」传不回教师端：课堂问答是一次性的，**没有沉淀**；
  - 想上 AI，但要装环境、接服务、配密钥，**门槛挡住了一线教师**；
  - 教材给的是**结论**，学生缺的是**过程**（→ 这条直接引出实训设计）。
- **示范开头**：
  > 一线教学里最耗费精力的不是「讲课」，而是围绕一堂课的所有来回：课前找材料、课中出题、
  > 课后收作业、再回头判断谁没跟上 —— 这些环节各用一套工具，成果互不相通。

### §3 系统设计（~800 字）★ 核心

- **该写什么**：三件事，各一小段：
  1. **整体形态**：为什么敢做成纯静态（部署成本为零、易分发、内网可用）。
  2. **双端架构**：一个固定外壳（顶部栏 + 侧栏）+ 中间内容区切换；
     **三层角色隔离**（内容页声明角色 → 两套菜单互不包含 → 跳转时越权拦截）。
  3. **数据怎么存**：浏览器本地存储 + **按账号分桶**（键形如 `基名:角色:账号`）——
     这是本系统最特别的一处，值得写透：说明「协同」是如何在无服务端条件下成立的。
- **可用事实**：
  - 存储分工：**偏好进 Cookie（小）、业务数据进 localStorage（大）**；
  - 账号隔离：**每个账号一个数据桶**；自注册账号从空开始，预置账号才带示例；
  - 跨端共享：教师发布的内容学生能看到，靠**跨桶读取 + 变更广播**；
  - 主题：Dark / Cream / Snow 三套，可切换；视觉令牌统一管理。
- **示范开头**（架构段）：
  > 系统由一个固定外壳和一组内容页组成：外壳承载导航与身份，内容页只负责一件事。
  > 页面之间通过一层薄薄的「路由」通信，鼠标点在哪里、身份是谁，两级校验都通过才会跳转。

### §4 关键功能与创新点（~800 字）★ 核心

- **该写什么**：**不要罗列功能清单**（清单在演示视频里看得到）。挑 **3 个**写深：
  - 每个创新点用「**普通做法 → 我们的做法 → 为什么更好**」三段式。
- **可选的三个创新点**【你定，挑三个】：

  ① **教学闭环，而不是功能堆叠**
  教师发布 → 学生学习 → 学习痕迹回流教师端，形成回路。
  *普通做法*：教师端、学生端各自独立。*我们的做法*：学生在课件上的批注、进度、推导，
  教师端**按课按人**看得到。

  ② **探究式实训：给路径，不给答案**
  学生可自行发起探究，AI 先给出「人类历史上这条路是怎么走出来的」引导骨架，
  带学生走完，并允许偏离。
  *普通做法*：AI 直接给答案。*我们的做法*：**终点答案不直接给** —— 全价值在过程中。

  ③ **诚实设计：不编、不装、不糊弄**
  拿不到的数据（真实的班级成绩）**直接不显示**，不造一个好看的数字；
  没配模型时相关功能**如实说明不可用**，不塞一段假内容冒充 AI 生成。

  ④ **无障碍不是开关，是真功能**
  阅读模式会真的改变排版（行高、限宽、加大点击目标），并支持**语音朗读**；
  朗读走浏览器自带语音合成，**不依赖任何模型**。

  ⑤ **教案版本链**
  教案与大纲的每一次修改都留版本，**任意两版可对比**，回退也是追加一条记录 ——
  用户永远不会因为点错而丢内容。

  ⑥ **工程可信度**（如果你的专业是这个，这条很吃香）
  全部功能由 **4 步自动化验证**守着：逻辑验证 → 真实渲染验证 → 跨身份数据流 → 端到端用户旅程。

### §5 AI 能力与「诚实设计」（~400 字）

- **该写什么**：
  1. 模型怎么接：**用户填自己的 Key**，浏览器直连三家国产模型（DeepSeek / 通义千问 / 智谱 GLM），
     **不经任何中转服务器** —— 这恰好是纯静态形态的天然优势：密钥不出本机。
  2. AI 干什么：出题、起草／改进教案、课件重讲、版本差异解读、把课表文本转成表格……
  3. **重点写这一段**：AI 的**边界**是怎么处理的（见 §4 创新点③）。
- **示范开头**：
  > 系统不内置任何密钥，也不经中转服务器：使用者填上自己的 API Key，
  > 由浏览器直接请求模型服务。密钥只存在于本机浏览器中，删掉即失效。

### §6 应用价值与推广（~200 字）

- **该写什么**：谁能用（一线教师 / 学生 / 教研室）、零部署怎么带来推广优势、内网场景。
- **可用的诚实表述**：本版本以**单浏览器**演示双端协同，多用户实时同步属推广阶段规划。

### §7 局限与后续规划（~200 字）

- **该写什么**：**主动**承认 4 条（评委一定会问，你先说胜过后被问）：
  1. 纯静态 → 协同是单浏览器模拟，真多用户需后端；
  2. 无服务端 → 凭据无法真正保密，定位是「校园内网系统的模拟」，**不是身份认证**；
  3. 学情数据：能真实拿到的（谁在这门课里）是真的，拿不到的（成绩）**不编、不显示**；
  4. 部分 AI 功能依赖使用者自备 Key。

## 5. 必须提前想好的三个口径（答辩必问）

| 会被问 | 建议口径 |
|---|---|
| 没有服务器，怎么协同？ | 「本版本以单浏览器演示双端协同，多用户实时同步属推广阶段规划。」 |
| 密码存在浏览器里，安全吗？ | **别说安全**。说：「定位是内网自建系统的模拟 + 入口仪式感，不是身份认证；正式版本应由后端签发会话票据。」 |
| 这些数据是编的吗？ | 「能真实拿到的就是真的（谁在这门课里、谁交了作业）；拿不到的不编，直接不显示。」 |

## 6. 演示视频分镜参考（3–5 分钟）

> 原则：**一条主线走到底，不逐页点**。观众要看到「闭环」，不是「页面很多」。

| 时间 | 画面 | 要点 |
|---|---|---|
| 0:00–0:25 | 教师端首页 | 一句话定位 + 侧栏全貌（让评委看到规模） |
| 0:25–1:00 | 教案：建大纲 → 加章 → 建课时 → 编辑 | 停在**版本链**，演示「任意两版对比」 |
| 1:00–1:30 | 出题与组卷 → 发布 | 讲「等确认才发布」的设计 |
| 1:30–2:00 | 切到学生端（同一浏览器换身份） | 学生看到刚发布的内容 —— **闭环的第一次证明** |
| 2:00–2:40 | 学生：阅读 → 批注 → 提问 → 交作业 | 期间开**无障碍阅读模式 + 朗读**，这是亮点 |
| 2:40–3:20 | 学生发起探究式实训 | 强调「**AI 给路径不给答案**」 |
| 3:20–3:50 | 切回教师端看该学生的进度与推导 | **闭环的第二次证明**（最出彩的一段） |
| 3:50–4:20 | 智能体 / 工作台 | 演示未接模型时**如实拒绝**，再填 Key 演示真生成 |
| 4:20–4:40 | 收尾 | 三句总结：闭环 · 双端 · 诚实 |

⚠️ 录制前**务必准备一个可用的 API Key**，否则视频里那几处会全是「还没接模型」的提示。

## 7. 避坑清单（写的时候照着划）

- ❌ 界面与文档里**不要出现「演示 XX」**这类词（数据来源类写「**预置示例**」）。
- ❌ 不要宣称安全 / 不要写「密码加密存储」。
- ❌ 不要写没有实现的功能（例如自动批改打分、真实多用户同步）—— 这些在答辩现场一点就穿。
- ❌ 不要把功能清单当设计文档：**3000 字里至少一半要讲「为什么这么设计」**。
- ✅ 数字要与系统里一致（用 §4 的表）。
- ✅ 主动写局限（§7），它体现的是判断力，不是短板。
